# markOS v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade markOS with:
- a boot screen;
- mac-style close, minimize and maximize buttons;
- resizable windows;
- a taskbar;
- a Spotify Music app with search and one-click play;
- a hamster mascot;
- clearer icons;
- a custom cursor.

**Architecture:** Same single page as v1. Small pure functions are unit-tested in Node: track filtering, resize maths, the taskbar decision, and hamster line picking. DOM wiring stays in `js/windows.mjs` (window state: minimized, maximized, resize) and `js/markos.mjs` (taskbar, boot, hamster, music wiring). A new `js/music.mjs` holds the track data, the filter, and the Spotify controller loader. The album navigation from v1 is removed.

**Tech Stack:** HTML, CSS, vanilla ES modules (`.mjs`), Web Audio (existing), Spotify iFrame API (`https://open.spotify.com/embed/iframe-api/v1`, loaded on first Music open), `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-21-markos-v2-design.md`. The v1 spec and `DESIGN.md` still apply.

## Global Constraints

- No libraries, no build step, no `package.json`. The only third-party script is Spotify's iFrame API, loaded only when Music first opens.
- Readable without JS. The `html.js`/`html.wm` fallback keeps working, and the boot overlay can only show under `html.js`.
- Boot: about 1.5s, skippable by any click, tap or key, once per session (`sessionStorage["markos-booted"] = "1"`, in try/catch), never under `prefers-reduced-motion`.
- Window button colours: close `#ff5f57`, minimize `#febc2e`, maximize `#28c840`; dots are 12px; each is a `<button>` with an `aria-label`.
- Minimum window size 320×220. The title bar stays reachable (`clampPosition`).
- The taskbar is 52px, desktop only, with icons in this order: hello.txt, Music, Projects, About, Skills, Contact.
- Spotify green `#1ED760`. Playlist `3QAwwmlzsDZjdNQOx1ldQH`. The 17 tracks come from the spec table, verbatim.
- WCAG AA, 16px body minimum, keyboard reachable, `prefers-reduced-motion` respected, sound off by default.
- Commit messages follow CLAUDE.md: `#<N> <Type>: <summary>`, where `N = git rev-list --count HEAD` + 1. **No Co-Authored-By line.**
- UI skill routing follows CLAUDE.md, and Ponytail stays on.

## Review Focus

1. **Music closed while a song plays:** close pauses playback, so nothing keeps playing unseen. Minimize keeps it playing, and the taskbar shows the playing bar. Covered by the Task 6 browser check.
2. **Spotify script blocked or offline:** the Music window still opens, and the list and a "Listen on Spotify" link still work. There are no uncaught errors. Covered by the Task 6 check, with the request blocked.
3. **Resizing past the minimum or off-screen:** the window never gets smaller than 320×220, and its title bar stays reachable. Covered by the `resizeRect` tests in Task 2.
4. **Searching with accents or capitals** (for example "ICY", "itzy", "Ê"): the right songs match, and an empty result shows "No songs match". Covered by the `filterTracks` tests in Task 2.
5. **Arriving on a deep link during boot** (`/#projects`): Projects opens once the boot ends. Reloading in the same session skips the boot. Covered by the Task 6 browser check.

### Task 2: Pure logic (track filter, resize maths, taskbar decision, hamster line)

**Files:**
- Create: `js/music.mjs` (data and filter only in this task)
- Create: `js/hamster.mjs`
- Modify: `js/windows.mjs` (add two pure exports)
- Test: `tests/music.test.mjs`, `tests/hamster.test.mjs`, `tests/windows.test.mjs` (extend)

**Interfaces (Produces):**
- `TRACKS: Array<{ title: string, artist: string, duration: string, id: string }>`: the 17 spec rows, in order.
- `PLAYLIST_ID = "3QAwwmlzsDZjdNQOx1ldQH"`.
- `filterTracks(tracks, query: string) -> tracks`. It matches title or artist and ignores case and accents (NFD, diacritics stripped). A query that is empty or only spaces returns every track.
- `resizeRect(rect: {x, y, w, h}, edge: "n"|"s"|"e"|"w"|"ne"|"nw"|"se"|"sw", dx: number, dy: number, min = { w: 320, h: 220 }) -> {x, y, w, h}`. Dragging an edge past the minimum stops at the minimum, and the opposite edge stays put.
- `taskbarAction({ open, minimized, focused }) -> "open" | "restore" | "minimize" | "focus"`. Not open gives "open"; minimized gives "restore"; open and focused gives "minimize"; anything else gives "focus".
- `LINES: string[]`: the six spec lines, verbatim.
- `pickLine(lines, last: string|null, rand = Math.random) -> string`. It never returns `last` while more than one line exists.

```js
// tests/music.test.mjs
import { test } from "node:test"; import assert from "node:assert/strict";
import { TRACKS, PLAYLIST_ID, filterTracks } from "../js/music.mjs";
test("17 tracks from the playlist", () => { assert.equal(TRACKS.length, 17); assert.equal(TRACKS[0].id, "1SaLI6o5GhfcaxPVAJoD3r"); assert.equal(PLAYLIST_ID, "3QAwwmlzsDZjdNQOx1ldQH"); });
test("empty query returns all", () => { assert.equal(filterTracks(TRACKS, "  ").length, 17); });
test("matches title or artist, any case", () => {
  assert.deepEqual(filterTracks(TRACKS, "aespa").map(t => t.title), ["Hot Mess", "Hold On Tight", "Dark Arts"]);
  assert.deepEqual(filterTracks(TRACKS, "icy").map(t => t.title), ["ICY"]);
  assert.deepEqual(filterTracks(TRACKS, "silk").map(t => t.title), ["Leave The Door Open"]);
});
test("ignores accents both ways", () => {
  const t = [{ title: "Ê Café", artist: "Zé", duration: "1:00", id: "x" }];
  assert.equal(filterTracks(t, "cafe").length, 1); assert.equal(filterTracks(t, "ZE").length, 1);
  assert.equal(filterTracks(TRACKS, "hearts2hearts").length, 2);
});
test("no match returns empty", () => { assert.equal(filterTracks(TRACKS, "zzzz").length, 0); });
```

### Task 3: Window manager gets minimize, maximize and resize

**Files:** Modify `js/windows.mjs`.

**Interfaces:**
- Consumes: `resizeRect` and `clampPosition` (Task 2, v1).
- Produces: `initWindows(root, { onOpen, onClose, onMinimize, isPhone, minimizeTarget })` returns `{ open, close, focus, minimize, restore, toggleMaximize, openIds, isMinimized, isFocused }`.
  - `minimizeTarget(id) -> Element|null` is the taskbar icon that the minimize animation shrinks into.
  - `minimize(id)` adds `.is-minimized` (the window stays in `openIds`), animates toward `minimizeTarget(id)`, and calls `onMinimize(id)`.
  - `restore(id)` removes `.is-minimized`, focuses the window, and animates out of the target.
  - `toggleMaximize(id)` toggles `.is-maximized`. It saves the inline left, top, width and height on entering and restores them on leaving. Double-clicking a title bar calls it.
  - `open` on a minimized window calls `restore`.
- Resize handles: the JS appends `<span class="win__resize" data-edge="n|s|e|w|ne|nw|se|sw">` to each `.win` (desktop only, not while maximized). Pointer-drag uses `resizeRect` and then `clampPosition`, and writes inline left, top, width and height.

### Task 6: Wiring (taskbar, Music controller, hamster, boot)

**Files:** Modify `js/markos.mjs`; extend `js/music.mjs` with DOM code.

**Interfaces:**
- Consumes:
  - `initWindows` (Task 3);
  - `filterTracks`, `TRACKS` and `PLAYLIST_ID` (Task 2);
  - `pickLine` and `LINES` (Task 2);
  - the DOM contract (Task 4).
- Produces: `initMusic(root: HTMLElement, { onPlayingChange(playing: boolean) }) -> { mount(), pause() }` in `js/music.mjs`.
  - `mount()` runs on first Music open. It injects `<script src="https://open.spotify.com/embed/iframe-api/v1" async>` and defines `window.onSpotifyIframeApiReady` once. It creates a controller in `[data-player]` with `uri: "spotify:playlist:<PLAYLIST_ID>"`, width 100%, height 152.
  - Clicking a track button calls `controller.loadUri("spotify:track:<id>")`, then `controller.play()`, and marks that button `aria-current="true"`.
  - The search input filters the list's `li` elements with `filterTracks`. With no match, `.music__empty` shows "No songs match '<q>'".
  - The controller's `playback_update` event calls `onPlayingChange(!e.data.isPaused)`.
  - `pause()` calls `controller.pause()` if one exists.
  - If the script fails to load (`onerror`), the player area shows the "Listen on Spotify" link only. Nothing throws.

Wiring in `markos.mjs`:
- **Taskbar:**
  - clicking `[data-task]` runs `taskbarAction({ open, minimized, focused })`, then the matching `wm` method (`open` goes through `openSection`, which sets the hash);
  - `.is-open` and focus state are kept in sync on `onOpen`, `onClose`, `onMinimize` and focus.
- **Lights:**
  - `[data-close]` calls `wm.close`;
  - `[data-minimize]` calls `wm.minimize`;
  - `[data-maximize]` calls `wm.toggleMaximize`.
- **Minimize and hash:** minimize clears the hash with `replaceState` (as close does), and restore leaves it alone.
- **Music lifecycle:**
  - `onOpen("music")` calls `music.mount()` the first time;
  - `onClose("music")` calls `music.pause()`;
  - minimize doesn't pause;
  - `onPlayingChange` toggles `.is-playing` on the Music taskbar button and the phone tile.
- **Routing:** `/#music` is now a normal section. Add `"music"` to `SECTIONS` in `router.mjs`, update the router test's "don't route" list to drop `#music` and add a case for `#music`, and remove the v1 `#music` scroll branch.
- **Removed:** the v1 `selectTrack`, `playBtn` and progress code.
- **Hamster:**
  - every 20–40s (random), when no bubble is showing and the tab is visible, set the bubble text to `pickLine` and add `.is-talking` for 4s;
  - hover or focus on the summary also writes the line into `[data-hamster-live]`, so it gets announced;
  - a click only toggles the menu (the native `<details>`);
  - under reduced motion there are no timed bubbles.
- **Boot:**
  - if `html.boot` is set, pick 3 status lines and cycle them;
  - after 1500ms, or on the first pointerdown or keydown, remove `boot` and set `sessionStorage["markos-booted"] = "1"` (via `writePref`);
  - route the hash only after the boot ends.
